# Report comments

Citizens and staff can discuss an existing report through the same flat, public discussion. Verified accounts can post plain text of 1–1,000 Unicode characters after trimming whitespace, and remove their own comments after confirmation. Display names and timestamps are public; account identifiers, contact details, and request metadata are never projected. Comments do not change report status or replace official service updates.

The shared panel belongs below the report context in citizen details and below published history in the authority dialog. It uses existing Public Sans, evergreen/neutral theme tokens and Material icons, with labeled multiline input, visible feedback, newest-first comments, refresh and explicit older-page loading. It remains usable on phones, dark mode, keyboard navigation, and enlarged text. Drafts survive read failures. Empty, loading, unavailable and uncertain-write states have clear recovery.

Supabase owns authorization and validation through three bounded RPCs: `list_report_comments`, `add_report_comment`, and `delete_report_comment`. Private rows have RLS and no API-role table grants. Reads require an existing report and a verified account. Posts use a client UUID as the comment identity, serialize identical retries, and reject reuse by another author or payload. Deletion erases the body and retains a private digest tombstone so delayed retries cannot resurrect removed comments. Report/account deletion cascades comments; an unavailable report rejects further discussion. No staff moderation, threads, reactions, notifications, attachments, or realtime subscriptions in this increment.

Pagination uses `(created_at,id)` keysets, at most 50 rows per RPC, with the client requesting 20. No offset drift when new comments arrive. A lost mutation response keeps the original UUID and locked draft until retry confirms its outcome. Account changes block stale-panel writes and discard stale responses. Demo discussions stay in memory and make no hosted calls.

The public comment `id` intentionally also serves as the request UUID; it is not a secret or authorization token. Replay binds that UUID to author, report and SHA-256 of the canonical body. Add/delete serialize on the same UUID. A deleted replay returns terminal HTTP 409 (`PT409`), allowing a deliberate new comment instead of recreating the old one. Deletion retries return the same acknowledgment. SQL trimming explicitly matches Dart Unicode whitespace; length counts Unicode code points. The exact server timestamp string is retained for cursors. Only one page request runs at a time; refresh cannot race an older-page request. Confirmed posts are inserted from their validated receipt without depending on a subsequent refresh. Stable panel keys preserve unresolved drafts across parent report reloads.

Explore also gains a compact search row and Filters button. Category, status and sort move into an accessible sheet with explicit Apply (`Show reports`), reset and cancel. Applied choices stay visible as small summaries, and search/reset behavior is preserved. The default filter bar should occupy less than 90 logical pixels on an ordinary phone.
